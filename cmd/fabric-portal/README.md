# Engineering Portal 契约评审与内部发布

运行 `go run ./cmd/fabric-portal`。服务默认监听 `127.0.0.1:8081`，连接 `http://127.0.0.1:8080` 的 Fabric API。使用 `IDP_FABRIC_PORTAL_HTTP_ADDR` 和 `IDP_FABRIC_PORTAL_API_URL` 可以指定绑定地址和 API 源站。

将门户放到内部门户的 OIDC 登录代理之后。代理完成登录和会话验证，并为请求在服务器端附上面向 Fabric API 的短时 `Authorization: Bearer …`。登录代理应保留浏览器的请求来源和原始主机名，供门户校验跨站提交。Fabric API 验证令牌，并对每个操作重新检查产品与 Workspace 权限。

作者可在提交面板为修订运行检查，可另选同一资产的一个修订作为兼容性对比基线。相同修订、基线、策略和工具的检查沿用已有记录；策略更新后检查证据过期，再运行一次即可得到新的检查。随后选择检查证据及审批范围，提交评审。评审人只查看检查，不运行检查。独立评审人打开队列和检查证据，批准或驳回。可豁免的规则需要逐条填写理由，本页面的豁免与批准同时到期。产品负责人可以浏览本产品队列。此入口仅转发流程使用的管理 API，门户及 API 响应禁止缓存。

发布人在已批准的评审详情中打开「Release 与内部发布」，填写版本并准备 Release，再选择内部目标与发布操作。撤销和恢复需要理由。提交前核对产品、目标、制品摘要及预期槽位代数。槽位展示当前代数、生效的 Release、批准问题和访问阻断状态，并列出最近操作。遇到并发更新时，页面刷新当前代数，由发布人核对后提交。

在「访问阻断与解除」中，安全管理员可阻断整个发布目标、其中的 API 资产或单个 Release。限定到资产或 Release 时填写事故中确认的编号。安全评审人可查看阻断记录，并在受影响发布撤销后独立解除。源站阻断、边缘传播状态和发布槽位分开显示。解除后由发布人单独恢复发布。

接入企业登录代理后，在隔离环境使用独立的作者、评审人和发布人账号执行该流程，并记录跨产品拒绝、撤权和制品读取结果。仓库的开发签发器可用于联调真实 API 与 PostgreSQL。

## WP-07 本地联调记录

2026-11-24 在 Chromium、真实 PostgreSQL 16.14 和开发签发器组成的隔离环境执行。作者提交 CargoPai 修订，独立评审人查看检查证据并批准，队列和修订状态均更新为已批准。产品负责人读得该决定，Parcel 账号只能选择 Parcel 产品，直接读取 CargoPai 队列时得到 404。

同一隔离环境中，独立发布人在浏览器准备 Release，并发布到 CargoPai 内部目标。验证了丢失响应时以同一个请求键重试只提交一次槽位操作，并发撤销后页面识别 412 并刷新代数。撤销后源站拒绝读取，恢复后读取到相同制品摘要。安全管理员在管理 API 施加 AccessBlock 后，门户显示阻断，源站拒绝读取。

2026-11-25 用相同环境复测独立安全角色。仅持产品级安全角色的账号可进入工作台，在浏览器执行目标、资产和 Release 三种范围的阻断。验证取消确认不产生操作、源站拒绝读取、跨产品查询被拒绝、发起账号无法自行解除，以及有生效制品时要求先撤销。独立安全评审人解除后槽位仍处于已撤销状态，发布人恢复后读到相同制品摘要。界面分别显示源站结果和边缘传播未知。

该记录覆盖 WP-07 中从评审到内部发布、撤销、阻断及恢复的本地联调。企业 IdP 登录、真实用户验收和边缘传播验证待执行。
