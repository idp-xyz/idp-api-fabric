# Engineering Portal 契约检查与内部发布

运行 `go run ./cmd/fabric-portal`。服务默认监听 `127.0.0.1:8081`，连接 `http://127.0.0.1:8080` 的 Fabric API。使用 `IDP_FABRIC_PORTAL_HTTP_ADDR` 和 `IDP_FABRIC_PORTAL_API_URL` 可以指定绑定地址和 API 源站。

将门户放到内部门户的 OIDC 登录代理之后。代理完成登录和会话验证，并为请求在服务器端附上面向 Fabric API 的短时 `Authorization: Bearer …`。登录代理应保留浏览器的请求来源和原始主机名，供门户校验跨站提交。Fabric API 验证令牌，并对每个操作重新检查产品与 Workspace 权限。

流程为“导入 → 检查 → 准备 Release → 发布”，不设评审人，也不需要批准（CR-0001）。这些工作都在「API 目录」的资产详情中完成，门户按当前 Workspace 的角色显示相应操作。此入口仅转发流程使用的管理 API，门户及 API 响应禁止缓存。

作者在修订面板运行检查，可另选同一资产的一个修订作为兼容性对比基线。记录后页面刷新该修订的检查，并打开这次检查的规则与发现。相同修订、基线、策略和工具的检查沿用已有记录，页面按响应状态说明是新记录还是已有记录；策略更新后再运行即得到新的检查。

修订面板的「兼容性比较」把该修订与同一资产的另一修订直接比较，默认以上一个修订为基线。结果给出整体判定（兼容、有风险、无法判断、破坏性）和每处变化的分类、代码和 JSON Pointer，判定用文字标明，不只靠颜色。这是比较，不是检查结论：准备 Release 以检查为准。

发布人在修订面板准备 Release：选择该修订的一条检查（默认最新一条），填写版本。页面列出结论为失败或未知的规则：可豁免的逐条填写一行理由，理由随 Release 记录；有不可豁免的规则时不能准备。检查不是按现行策略和工具完成的，Fabric API 拒绝准备，需重新运行检查。提交前核对资产、修订、检查、版本及豁免的规则。发布人无需独立，同一人可以导入、检查、准备 Release 并发布。

资产详情的「发布」列出每个内部发布目标的槽位状态、代数、生效的 Release、访问阻断和边缘传播状态，以及最近操作。发布人可选择 Release 发布、撤销或恢复，撤销和恢复需要理由。提交前核对产品、目标、制品摘要及预期槽位代数。丢失响应后重试沿用同一个请求键；遇到并发更新时，页面刷新当前代数，由发布人核对后提交。替换另一修订已发布的 Release 时，所发布 Release 依据的检查须以那个修订为对比基线。

在「访问阻断与解除」中，安全管理员可阻断整个发布目标、其中的 API 资产或单个 Release。限定到资产或 Release 时填写事故中确认的编号。安全评审人可查看阻断记录，并在受影响发布撤销后独立解除。源站阻断、边缘传播状态和发布槽位分开显示。解除后由发布人单独恢复发布。

进入门户后先看到「工作台」，汇总当前 Workspace 等待处理的事项：最新检查失败的资产、已检查但还没准备 Release 的修订，以及被访问阻断的发布。每一项都在「API 目录」中打开对应的资产详情。读不到的部分单独说明原因。

「API 目录」列出当前 Workspace 的 API 资产，可按关键字、类型、最近检查结论和“已检查、未准备 Release”筛选。筛选和分页都由 Fabric API 在服务端完成，看不到的资产不会下载到浏览器。每个资产显示最新修订、最近检查和最新 Release。打开资产后，按从新到旧列出修订及其源文件摘要和引用闭包摘要；选中某个修订，显示它的检查、Release 及其豁免；CR-0001 之前留下的评审列为「历史评审」，只读。在旧审批下准备的 Release 标为「旧审批」。产品负责人和内部读者只能查看。读不到某一部分时，只在该部分显示原因。

接入企业登录代理后，在隔离环境分别使用作者、发布人、兼任两者的账号和安全角色账号执行该流程，并记录跨产品拒绝、撤权和制品读取结果。仓库的开发签发器可用于联调真实 API 与 PostgreSQL。

## WP-07 本地联调记录

以下记录早于 CR-0001，当时准备 Release 仍须独立评审人先批准。

2026-11-24 在 Chromium、真实 PostgreSQL 16.14 和开发签发器组成的隔离环境执行。作者提交 CargoPai 修订，独立评审人查看检查证据并批准，队列和修订状态均更新为已批准。产品负责人读得该决定，Parcel 账号只能选择 Parcel 产品，直接读取 CargoPai 队列时得到 404。

同一隔离环境中，独立发布人在浏览器准备 Release，并发布到 CargoPai 内部目标。验证了丢失响应时以同一个请求键重试只提交一次槽位操作，并发撤销后页面识别 412 并刷新代数。撤销后源站拒绝读取，恢复后读取到相同制品摘要。安全管理员在管理 API 施加 AccessBlock 后，门户显示阻断，源站拒绝读取。

2026-11-25 用相同环境复测独立安全角色。仅持产品级安全角色的账号可进入工作台，在浏览器执行目标、资产和 Release 三种范围的阻断。验证取消确认不产生操作、源站拒绝读取、跨产品查询被拒绝、发起账号无法自行解除，以及有生效制品时要求先撤销。独立安全评审人解除后槽位仍处于已撤销状态，发布人恢复后读到相同制品摘要。界面分别显示源站结果和边缘传播未知。

该记录覆盖 WP-07 中从评审到内部发布、撤销、阻断及恢复的本地联调。企业 IdP 登录、真实用户验收和边缘传播验证待执行。
