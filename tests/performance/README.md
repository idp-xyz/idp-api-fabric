# Product Governance 列表负载实验

用于收尾 PR #6 / #7 的本地工程证据。测量实际组装的 HTTP 路由、OpenAPI 参数校验、JWT 签名/JWKS 验证、应用授权和 PostgreSQL 查询；数据库使用迁移角色建库、应用角色访问，测试结束删除独立临时数据库。IdP 使用本地开发替身，数据为合成数据。

本实验不改变 F03/F05/F08 的正式验收矩阵，不替代生产 IAM、安全评审、正式 SLO 或生产容量验收。

## 复现

在仓库根目录执行，先启动 compose.yaml 中的 PostgreSQL 16.14。连接信息仅适用于这个可丢弃的本地测试容器。

```bash
make db-up
export IDP_FABRIC_MIGRATOR_DSN='postgres://fabric:fabric@127.0.0.1:55450/postgres?sslmode=disable'
export IDP_FABRIC_POSTGRES_DSN='postgres://fabric_app:fabric_app@127.0.0.1:55450/postgres?sslmode=disable'
make check

export IDP_FABRIC_LIST_LOAD=1
export IDP_FABRIC_LIST_LOAD_DURATION=3s
export IDP_FABRIC_LIST_LOAD_REPORT="$PWD/tests/performance/lists-$(date -u +%Y%m%dT%H%M%SZ).json"
go test -v -count=1 -timeout=10m ./cmd/fabric-api -run '^TestProductGovernanceListLoad$'
```

负载实验独立执行，不与 make check 或其他负载并行；不要加 `-race`，竞态检查由前面的 make check 完成。时长可配置为 1s–1m。默认 CI 跳过本实验；显式启用后缺少任一 DSN 或报告路径会失败。输出文件必须不存在，避免覆盖先前证据。报告不写 DSN、JWT、私钥或主体凭证。

## 数据与方法

- 20,001 个 Product、40,001 个 Workspace、80,200 条成员关系、22,201 条负责人分配，行数由数据库实际查询核对；使用最新迁移并执行 ANALYZE。
- Product 管理员全量列表、Product 负责人可见列表、Workspace 负责人列表、Workspace 成员过滤列表、成员列表、负责人列表，共六条查询路径。负责人在全部产品中持有 201 个产品；普通成员只属于目标产品的 200 个 Workspace。
- 先通过真实 API 游标遍历列表，检查完整数量、ID 无重复和终止条件，再选择首屏和中间位置的页，每页最多 100 条。所有计时请求验证 ID 集合及顺序、下一页令牌和 no-store 响应头与准备阶段一致。
- 每条路径分别使用 1、8、32 个并发客户端，固定时长闭环请求、复用 HTTP 连接。另以 32 并发请求无权查看的负责人列表（预期 403）和陌生人的 Workspace 列表（预期 404），检查拒绝未携带列表内容。
- 延迟包含 HTTP 往返、读取及验证响应体，统计全部请求的最近秩 p50/p95/p99/max；吞吐按实际完成请求数除以含在途请求完成时间的墙钟时间。任何状态、内容或网络异常都计入 errors，非零则实验失败；预期 403/404 不算错误。
- 客户端与服务端同机，JWKS 和数据已预热，无思考时间、无固定到达速率。结果只适用于这一合成数据与短时闭环负载，不用于推断开放流量下的排队、长时间稳定性、冷缓存、远程网络或生产峰值容量。原始报告记录应用提交、压测源码摘要、Go/PG 版本、CPU/GOMAXPROCS、连接池上限和每个场景的观测值。
