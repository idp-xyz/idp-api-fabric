# CR-0001 — 内部使用不再设审批

- **状态**：已决定。决定 1、2 由老板决定，2026-11-26；决定 3–6 经老板授权由开发侧决定，2026-11-26。
- **依据**：F08 §1.2 范围变更协议。批准前的范围（独立评审人批准后才能准备 Release）在实现合并前仍然有效。
- **关联**：F01 FR-017、FR-028、FR-031、FR-034、FR-043、NFR-12；F03 `ReviewDecision`、INV-07；F04 F04-GOV-016、F04-GOV-025，§11.4–§11.6；F05 AC-03、AC-04、AC-35、AC-50–AC-54；F06 IN-06；ADR-0008。

## 触发源
老板决定：Fabric 只供内部使用，不需要独立评审人，也不需要审批这一步。

## 决定
1. **准备 Release 以检查为准。** 准备 Release 时指定该修订的一条检查，这条检查须在现行策略和工具下完成。结果为 `FAIL` 或 `UNKNOWN` 的规则（与原先批准时的要求相同，不分阻断级和警告级）须按决定 2 豁免，否则不能准备 Release。阻断级规则的 `NOT_RUN` 只允许出现在现有 `outsideContractChecks` 列出的规则上，即在检查之外执行的 10 条，以及没有选对比基线时的兼容性规则 F04-GOV-013。不再要求批准。
2. **豁免在准备 Release 时填写。** 只对可豁免的规则开放，由准备 Release 的人逐条填写理由，理由记入 Release 的来源记录。豁免必须恰好覆盖需要豁免的规则，和现在批准时的要求一致。不可豁免的安全、完整性规则为 `FAIL` 或 `UNKNOWN` 时，不能准备 Release。
3. **不再要求发布人独立。** 同一个人可以导入、检查、准备 Release 并发布。访问阻断和解除仍由安全角色负责，解除仍须由另一位安全评审人执行。
4. **旧评审记录保留，只读。** 已有 Release 继续引用其评审。评审的读取接口保留，提交、撤回和决定接口删除，此后不再产生新评审。上线时仍在评审中的请求记为撤回，理由引用本 CR，已有结论不改。
5. **策略更新后，已有 Release 仍可发布和恢复。** 它在准备时已经检查过。只有准备新 Release 时才要求现行策略下的检查。
6. **`internal_reviewer` 不再授予。** 已有授予不再带任何写权限，持有人仍可读取历史评审。

## 影响
- **领域**：Policy & Review 不再产生 `ReviewDecision`。新的 Release 关联它所依据的检查，不再关联评审。INV-07 中“批准仅对匹配内容、范围和有效期有效”改为“Release 仅依据匹配内容、现行策略下的检查及其豁免”。F03 把“假定 PASS 检查即可部署”列为反模式，本决定改为：检查门禁取代人工批准，门禁的内容见决定 1。
- **契约**（管理 API，破坏性变更）：
  - 删除 `requestRevisionReview`、`withdrawRevisionReview`、`decideRevisionReview`。
  - `prepareContractRelease` 的请求体用 `check_run_id` 取代 `review_id`，并增加豁免列表（`rule_id` 与理由）。
  - 发布槽位删除 `approval_problem`。`APPROVAL_*`、`WAIVER_EXPIRED`、`REVIEWER_*`、`PUBLISHER_NOT_INDEPENDENT`、`REVIEW_*` 不再返回。
  - `listRevisionReviews`、`getRevisionReview`、`listWorkspaceReviews` 保留，只读。
- **安全**：取消两处双人控制，即作者与评审人、作者与发布人。保留的控制有：
  - 检查门禁，不可豁免规则不能绕过；
  - 按角色授权，包括作者、发布人和安全角色；
  - 访问阻断，解除仍须由另一位安全评审人执行；
  - 审计记录。

  F05 中 AC-03、AC-35、AC-50、AC-51 删除；AC-04 去掉 `decision.valid`；AC-52–AC-54 改为只读历史。待拍板事项中关于评审队列可见范围的一条不再需要裁决。
- **规则**：F04-GOV-016 改为“准备 Release 时核对检查、现行策略和豁免”。F04-GOV-025 不再适用。ADR-0008 要解决的是评审人读不懂检查结论；取消评审后，准备 Release 只看逐条规则的结果，ADR-0008 可以不再推进。
- **UX**：门户流程改为“导入 → 检查 → 准备 Release → 发布”。评审队列和决定表单删除，IN-06 改为“检查与准备 Release”。

## 成本与进度
- **后端**：改动最大，包括准备 Release、发布时的核对、数据库迁移（Release 关联检查、记录豁免）和约 70 个测试文件。
- **门户与文档**：随后修改门户，并同步 F03–F08。

按 F08 §4.1，工时由具名负责人在计划中填写，这里不给数字。

## 兼容性
- 已有 Release、槽位和评审记录不变，继续可读。
- 管理 API 的调用方要改用 `check_run_id` 准备 Release。门户随实现同步更新。

## 证据重跑集
- `make check`；
- F03–F06、F08 校验、一致性校验和 MANIFEST；
- 在隔离环境重跑门户联调：导入 → 检查 → 准备 Release（含豁免）→ 发布 → 撤销、恢复、阻断。

历史验收记录不改，新的结果另行记录。
