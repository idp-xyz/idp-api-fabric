# ADR-0001 — 联邦式跨产品 API 治理架构

- **状态：Proposed（方向已讨论，待 F02 正式审核）**
- **日期：2026-11-09**
- **关联文档：** `docs/F01_Product_Requirements.md`

## 背景

CargoPai、IDP Parcel、IDP Brant、IDP Prism 等供应链产品具备独立的领域模型、合作伙伴与 API 生命周期，但共享契约规范、验证、目录和文档交付等需求。

## 拟议决策

采用一个统一的 API Fabric **治理平台**，各产品保持自己的契约、发布策略和授权边界；内部统一工程管理门户、外部按产品品牌隔离的开发者门户共存。不建立覆盖所有产品的单一业务 API 模型或单一巨型 OpenAPI 文档。

## 考虑过的方案

1. 产品逐个独立建设全部能力：自治较强，但重复开发及长期治理成本高。
2. 所有产品 API 完全统一到一个工程与契约：短期集中，跨业务语义及发布耦合风险过高。
3. **统一治理、产品自治（推荐）：** 标准与工具复用，同时保留产品发布和权限边界。

## 后果与待验证项

- 需要产品 / Workspace / 组织 / 消费者独立建模及授权矩阵。
- 需要 Git、Registry、Catalog、Publication 的事实权威与一致性设计。
- 部署独立性、Gateway/IAM 适配、成本和容量须在 F02/F05/F07 确定。

**本 ADR 尚未正式批准，不构成 F02 技术选型已冻结的证据。**
