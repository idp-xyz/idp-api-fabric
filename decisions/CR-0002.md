# CR-0002 — 内部使用从简：四处设计与实现不一致的裁决

- **状态**：已决定。项目开发负责人，2026-11-26，依据 CR-0001 确立的内部使用从简方向。
- **依据**：F08 §1.2 范围变更协议。
- **关联**：F02 §18.2 D-08；F03 §3.3、§5.10、§5.12、§5.13、§16（OD-09）；F04 F04-GOV-015，§11.8、§11.10；F05 AC-16、AC-29，§6.7、§6.9、§6.10、§6.14、§6.15；F06 §6；CR-0001。

## 触发源
团队决策单事项一 #1–#4 列出的四处设计与实现不一致：

1. 按编号下载 Release（`getContractReleaseArtifact`）不看访问阻断，设计正文写的是下载要看阻断（F05 §6.9）。
2. 审计记录里的行动人按原值给出，设计要求只展示脱敏主体（F06 §6，F05 AC-29 的 `fields.minimized`）。
3. 平台管理员只来自部署配置 `IDP_FABRIC_PLATFORM_ADMIN_SUBJECTS`，没有放在库里、可撤销且有记录的角色（F05 §6.10）。
4. 目录列表没有 F03 §3.3 设计的可重建投影 `AssetSearchIndex`，资产概况在读的时候算（F03 §5.13）。

CR-0001 确立的方向：Fabric 只供内部使用，保持简单。

## 决定
1. **按编号下载看这个 Release 的阻断（改代码）。** 产品的任一发布目标上有范围就是这个 Release 的访问阻断，而且没有解除时，按编号下载被拒绝；解除以后恢复。不管这个 Release 在不在那个目标上生效过。目标级和资产级的阻断仍不影响按编号下载：它们管的是一个目标提供什么。产品暂停时仍可按编号下载，不变。Release 的元数据和来源（`getContractReleaseProvenance`）照常读取，不变。
2. **审计员看到真实的行动人（只改文档）。** 审计记录对本产品的审计员如实给出签发方和主体，这是内部使用的本意。去掉“审计只能展示脱敏主体”的设计要求和 AC-29 的 `fields.minimized`。导出需要额外权限、审计不可编辑，不变。
3. **平台管理员留在部署配置（只改文档）。** `IDP_FABRIC_PLATFORM_ADMIN_SUBJECTS` 是内部使用下认可的设计，不改成库里的角色。运行要求：fabric-api 的每个副本带同一份设置；设置的改动走部署自身的变更控制，Fabric 不审计这项改动。
4. **暂不建 `AssetSearchIndex`（只改文档）。** 资产概况在读的时候算是认可的设计。资产数量需要时再建索引。

## 影响
- **领域**：阻断的事实仍归 Publication。Contract Registry 经端口问 Publication 一个 Release 有没有未解除的阻断，不读 Publication 的表。读阻断时，先对产品的全部发布目标加共享锁，与经槽位读制品时对一个目标加锁的方式和顺序相同，所以放置和解除阻断与下载有确定的先后。F03 §3.3 的 `AssetSearchIndex` 改为资产数量需要时再建。F03 OD-09（审计里的个人信息与删除请求的冲突）不在决定 2 里，仍待 F05 和法务。
- **契约**（管理 API 0.38.0，增加一种拒绝）：
  - `getContractReleaseArtifact` 在阻断未解除时答 409 `RELEASE_ACCESS_BLOCKED`，操作声明了 409。
  - `getPublishedArtifact`、`blockPublicationAccess` 的描述补了文字。没有新操作，没有新 schema，操作数仍是 57。
- **安全**：
  - 阻断一个 Release 以后，它的字节在 Fabric 的两条读取路径上都读不到：经槽位读只对阻断所在的目标，按编号下载不分目标。
  - 拒绝记 DENY-03、`release.download`，与没有授权的拒绝、经槽位读被阻断的拒绝记法相同。不能下载的人先因为没有授权被拒绝，得不到阻断的消息。
  - AC-29 的条件去掉 `fields.minimized`，`change_ref` 记 CR-0002；AC-16 不改，它的 `accessblock.absent` 对按编号下载按决定 1 理解。矩阵仍是 54 行。
  - 平台管理员配置的一致和改动的记录由部署负责。
- **UX**：F06 §6 的审计一条改为如实展示行动人，F06-A 离线原型审计页的说明随之改。门户不按编号下载，不用改。

## 兼容性
- 管理 API 0.38.0。调用方要处理 409 `RELEASE_ACCESS_BLOCKED`：0.37.0 下载成功的，Release 被阻断时现在被拒绝。
- 没有迁移，不需要重新授权，没有新配置。旧进程仍不看阻断，所以全部 fabric-api 进程换完以后，阻断才对每次按编号下载生效。
- 放置或解除阻断要等同一产品里正在进行的按编号下载结束，按编号下载也要等正在放置或解除的阻断，与经槽位读相同。
