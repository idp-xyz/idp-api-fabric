# ADR-0004 — Release 不可变与 PublicationSlot 生效指针分离

- **状态**：Proposed（设计候选，未具名签核）
- **日期**：2026-11-09
- **文档基线**：V1.0（不单独递增工程基线）
- **关联**：F02 §7/§9/§13；F01 FR-017/031–036、AT-08/09。

## 背景
契约历史不应因回滚被改写。数据库事务无法同时原子更新对象存储、搜索索引、CDN。

## 推荐决策
正式 ContractRelease 内容寻址且不可变；`PublicationTarget` 仅定义 Product × Audience × Environment × Portal 的分发范围，不持有单一全局生效 Release。每个 Target 内每个 `APIAsset` 拥有独立 `PublicationSlot`，数据库必须确保 `UNIQUE(target_id, api_asset_id)`，并验证 Target 与 APIAsset 属于相同 Product。

**唯一生效权威**：`PublicationSlot.active_release_id`（可为空）及单调递增的 `generation`；发布、撤销、回退必须按指定 `slot_id` / `(target_id,api_asset_id)` 进行 `expected_generation` CAS，提交操作历史/审计与 Outbox；同 Slot 并发冲突，不同 Slot 独立。Release 必须属于同一 APIAsset，且审批、可见范围与当前策略匹配。Catalog、门户导航和搜索仅为可重建投影。

**阻断独立于指针**：`AccessBlock` 可以覆盖 Target 全域、单个 Slot 或制品访问路径；Target-wide deny 不代表 Target 拥有 current_release 指针，也不能自动更改其余 Slot 的历史/代数。先 Stage 后 Commit，异步对账；错误公开先同步 Origin/Edge deny，再对受影响 Slot 撤回或回退，缓存残留未证实清除时保留 `UNKNOWN/AT_RISK`。

## 备选方案与权衡

- **可变 Release 及 latest 覆盖**：历史不可追溯，无法进行可靠回退。
- **完全依赖静态 CDN 发布**：部署简单，敏感内容撤销风险高。
- **不可变 Release + Slot 级原子指针 + 可重建投影（推荐）**：精确到每 API，能够独立发布、撤销、恢复，避免同 Target 内 API 相互覆盖。

## 后果与约束
`PublicationTarget` 没有单一当前 Release；单 Slot CAS 事务不意味着全球 CDN 瞬时一致；需对私有访问每次授权，Edge/Origin deny 必须真实可验证。

## 关闭条件与证据
同 Slot 并发 CAS 只一方成功；不同 Slot 可同时发布；Target-wide Block 生效时应拒绝所有 Slot 的读取但不变更它们的历史指针；另需对象存储失败、Edge 延时、匿名残留访问、单 Slot 回退与恢复演练。上述运行测试均 NOT_RUN；需要 Architecture/Domain/DB/Security 具名批准。
