# CR-0003 — Fabric 是否承担外部提供方 API 的出站路由发布

- **状态**：已决定（项目开发负责人，2026-11-26）：接，放在 V1，MVP 范围不变；决定 4 还要网关负责人书面接受。实现之前先与网关负责人对齐 ADR-0009 的问题；在实现之前，Fabric 不向网关发布任何东西，管理 API、数据库和 F01–F08 正文（F08 §1.2 的已批准范围变更表除外）都不因本 CR 改变，正文随实现同步。
- **依据**：F08 §1.2 范围变更协议。
- **关联**：[ADR-0009](ADR-0009.md)（Proposed）；CR-0001、CR-0002；F01 非目标 2 和 7，FR-004、FR-007、FR-010、FR-025、FR-032–036、FR-039、FR-045、FR-060，NFR-02、NFR-05、NFR-10，DEC-06；F02 §12.3、§13.2，D-03；F03 §2、§5.10、§8.3；F04 §2、§3.2、§5.1、§10、§11.6；F05 §4.1、§6.7、§9、§12、§13；F08 §4.1、§7、§9.3、§17，OD-08-04，WP-10，MS-07；网关 ADR-0006、网关 ADR-0020。网关文件的来源和引用写法见 ADR-0009 抬头。

## 触发源

网关已经把出站路由的发布批准分给 Fabric，网关一侧的适配器做好了，在等 Fabric 一侧：

- 网关 ADR-0006（Accepted，2026-11-21）：Fabric 管 APIAsset、Release、PublicationSlot 及审批；网关管原生代理配置和观察到的状态；两边经版本化意图和受控适配器协作，各有自己的存储。
- 网关 ADR-0020（Accepted，2026-11-24）：`gateway-fabric` 收 `POST /v1/route-intents` 和 `GET /v1/route-intents/{intent_id}/status`，mTLS，同步校验失败 422，幂等和代次冲突 409，受理 202 为 `DRAFT`，状态只用契约 `ReleaseState` 的 16 个词；登记表的 `policy_version` 由网关按池代次生成，不由 Fabric 送（同篇“做出来了（V1.0）”）。回环套件里 Fabric 一侧是替身客户端。同篇抬头记了网关所有者的阶段 0 范围：“新路由与认证方案声明走 API Fabric”。
- 网关开发计划 §6：这项对接“要等……Fabric 一侧”。
- 网关的变更清单（`docs/integrations/Fabric_and_Gatekeeper_Change_Impact.md`，Proposal）列出它希望 Fabric 在 F01–F08 改的地方，没有改 Fabric 文档，要 Fabric 的 Owner 接收。

Fabric 现在没有外部提供方 API 这个概念，发布目标只有门户（ADR-0009“Fabric 现在有什么”）。

## 决定事项

1. **接不接。**
   - **A. 不接。** 网关继续用 `gateway-control compile` 和 `publish` 发布，Fabric 只保留 F02 §12.3 的适配协议。网关 ADR-0006 的分工落空，网关阶段 0 的范围要由网关所有者另定。
   - **B. 接。** 按 ADR-0009 的方案与网关负责人对齐后实现：外部提供方 API 是资产的一种来源；新增网关路由目标；一次激活按路由表展开成若干条发布意图；`approval_ref` 指向 Fabric 的 Release 和它的检查；`fabric-worker` 用工作负载证书提交并读回状态。
   - **已决定**（项目开发负责人，2026-11-26）：B，接。
2. **放在哪个阶段**（选 B 时）。
   - **MVP。** WP-06、WP-07、WP-09 和 MS-04、MS-05 要加入网关目标。按 F08 §9.3，外部适配不提供测试接口时相关端到端门禁不能通过，MVP 签收就要等网关。网关自己的生产前提在它的阶段 2（网关 ADR-0020 推荐决策 7）。
   - **V1。** 与 FR-039（漂移）、FR-045（连接状态）、FR-060（网关元数据适配接口）和 WP-10（IAM/Gateway 适配）同期，MVP 范围不变。
   - **已决定**（项目开发负责人，2026-11-26）：V1。
3. **外部提供方 API 归哪个产品**（选 B 时）。ADR-0009 第 1 条建议单设一个平台产品，每家提供方一个 Workspace。
   - **已决定**（项目开发负责人，2026-11-26）：按建议，单设一个平台产品，每家提供方一个 Workspace。出站池是按流量类和环境分的平台资源，不属于某一个业务产品（ADR-0009 第 1 条）；这是 Fabric 内部怎么建模，不改变网关的接口，也不改变其他产品。
4. **网关路由要不要保留一道批准**（选 B 时）。网关把“API Fabric 批准路由意图”当作产品功能（网关 ADR-0006；网关 `docs/governance/README.md` 写明它不受网关项目自身取消批准人的影响），CR-0001 则取消了 Fabric 的审批。
   - **沿用 CR-0001。** `approval_ref` 指向 Release 和它依据的检查，Fabric 的发布门禁就是批准（ADR-0009 第 5 条）。需要网关负责人接受。
   - **网关路由例外。** 发往网关的路由由另一人确认后才提交。出站路由会让内部工作负载以承运商账户对外调用，风险高于文档发布；代价是在 Fabric 里为这一类目标重新引入一道确认。
   - **Fabric 一侧已决定**（项目开发负责人，2026-11-26）：沿用 CR-0001，不为网关路由另设确认。要网关负责人书面接受才算定下（ADR-0009 第 5 条第 2 点、问题 9）。网关负责人不接受时，是否改为“网关路由例外”另行决定：那会重新引入 CR-0001 决定 1、3 取消的批准和独立，交老板决定。

决定 1、2 按开发侧建议：选 B，放在 V1。理由：网关已经把批准分给 Fabric，不接就要网关另起一套批准；F01 把网关元数据适配接口排在 V1（FR-060），但发布外部提供方 API 的出站路由超出了它，是需求新增（见“上游 FR/NFR”），按 F08 §1.2 记为范围变更；提前到 MVP 会让 MVP 签收依赖网关的进度。决定 4 沿用 CR-0001 的理由：Fabric 只供内部使用（CR-0001），出站路由也只给内部工作负载用，方向一致。ADR-0009 P0 里不写代码的对齐现在就可以开始。

## 上游 FR/NFR

| 需求 | 现在 | 选 B 之后 |
|---|---|---|
| 非目标 2 | 不自建网关的流量转发 | 不变：Fabric 只送意图，不转发、不编译网关配置 |
| 非目标 7、FR-034、NFR-02 | 文档不授权接口；公开内容须明确授权 | 外部提供方 API 不发布到 `partner`、`public` 目标；路由生效不授予任何账户 |
| FR-004 | 区分平台产品、开发者组织、Consumer Application | 新概念叫“外部提供方 API”，与 Consumer Application 分开 |
| FR-007、FR-010 | 资产有接口类型 | 资产另有来源和提供方 |
| FR-025 | 发布前检查凭证和敏感示例 | 增加 ADR-0009 第 2 条的规则 |
| FR-032 | Release 发布必须指定产品、受众、环境和门户 | 网关路由目标没有受众和门户，措辞要改 |

| FR-060（V1） | 网关元数据适配接口 | ADR-0009 是它的一种实现 |
| NFR-05 | 发布状态与补偿确定 | Fabric 的决定和网关的观察分两种状态记录 |

## 受影响领域/契约/安全/UX

- **领域。** API Catalog 的资产增加来源和提供方；Publication 增加网关路由目标、路由表、提交条目、回读记录和已知代次，槽位、操作和阻断沿用；Policy & Review 增加规则。详见 ADR-0009“影响”。
- **契约。** Fabric 管理 API 加一个小版本：新增资源和可选字段，`PublicationAction` 增加 `RESUBMIT`，新增五个错误码；现有 57 个操作的行为不变。网关的契约不因 Fabric 改变；网关答复 ADR-0009 问题 5、6 之后，网关契约可能升版。
- **安全。** `fabric-worker` 多一条出站 mTLS 连接和一份私钥；授权矩阵和威胁登记册各加几条；CR-0001 取消的双人控制在路由发布上同样不存在；Fabric 不能撤销账户或封禁操作，网关的紧急停止不经 Fabric。
- **UX。** 内部门户：资产登记、网关路由目标登记、槽位的路由状态，文档发布与路由生效分开显示；F06 页面清单要加页面。外部开发者门户不变。

## 成本与进度

- **后端**：资产来源，网关路由目标与路由表，提交队列和 worker 的 mTLS 客户端，状态回读，`RESUBMIT`，迁移和授权，测试（包括对着真实 `gateway-fabric` 的回环）。
- **门户**：资产登记、目标登记、槽位的路由状态。
- **文档**：F01–F06、F08 正文，F05 资产，F06 页面清单，两份 README。
- **外部依赖**：网关负责人对 ADR-0009 问题的答复；P1 要网关把 `gateway-fabric` 部署到测试池；P2 要等网关的阶段 2。进度受这些约束，Fabric 不能单方面排定。

按 F08 §4.1，工时由具名负责人在计划中填写，这里不给数字。

## 兼容性

- **选 A**：没有变化。
- **选 B**：
  - 管理 API 只增不删。现有资产记为 `IDP_OWNED`，现有目标记为 `PORTAL`，行为不变。`PublicationAction` 的新成员 `RESUBMIT` 对把动作当作封闭集合的客户端属于 `RISKY`（F04 §5.1）。
  - 迁移只加列和表，不改现有记录的含义；应用角色要按迁移重新授权（`fabric-migrate -apply -grant-to <application_role>`）。
  - 网关接口按网关现有契约实现；网关契约升版时 Fabric 跟着改。
  - 网关一期要求一个池只有一个写入方（网关 ADR-0020“成本与剩余风险”）。接入之后，那个池由谁发布要与网关负责人约定（ADR-0009 问题 15）。
