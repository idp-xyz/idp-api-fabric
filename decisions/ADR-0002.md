# ADR-0002 — 控制平面采用 Go 模块化单体与独立 Worker

- **状态**：Proposed（设计候选，未具名签核）
- **日期**：2026-11-09
- **文档基线**：V1.0（不单独递增工程基线）
- **关联**：F02 §4–5、§8、§15；F01 FR-007–036、NFR-11。

## 背景
治理、发布与目录在 MVP 中存在强协作和事务性要求。过早微服务化会增加一致性与运维负担。

## 推荐决策
采用 Go 模块化单体承载控制平面；以语义模块划分 BC，持久 Worker 用独立进程部署，业务运行时 API 不纳入 Fabric。

## 备选方案与权衡

- **多微服务**：可独立部署，跨上下文事务、接口和故障复杂度上升。
- **单体含所有同步长任务**：实施简单，但受长任务与用户交互相互影响。
- **模块化单体 + 分离 Worker**：优先候选，控制初期复杂度，同时提供独立伸缩点。

## 后果与约束
跨 BC 依赖必须静态检查；工作负载和高风险域有证据后允许拆分；不得将 BC 数量当作服务数量。

## 关闭条件与证据
进行双 Portal + 端到端发布 PoC、并发压力试验、Worker 中断恢复；实际证据 NOT_RUN。

> 本 ADR 是架构决策提案。若 PoC、F03–F08 设计或安全审查发现不可满足的约束，必须重新评审；不得将“Proposed”描述为“Approved”。
