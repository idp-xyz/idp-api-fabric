# ADR-0005 — 内外双门户独立安全面并共享文档引擎

- **状态**：Proposed（设计候选，未具名签核）
- **日期**：2026-11-09
- **文档基线**：V1.0（不单独递增工程基线）
- **关联**：F02 §6/§10/§11；F01 FR-040–055、NFR-15。

## 背景
内部工程审核/发布与外部 API 阅读/接入的身份、信任、会话、内容权限和交互任务不同。

## 推荐决策
内部 Engineering Portal 与各 Product Developer Portal 分离安全配置、授权与可见范围；复用受控 Registry、文档渲染、UI Token。实现上可共享前端代码基础，但外部只暴露 allowlist 的文档查询/自助能力。

## 备选方案与权衡

- **所有用户同一统一门户**：复用高，但内部操作误曝与体验耦合风险大。
- **所有产品独立复制完整门户**：品牌独立，但重复研发与版本漂移。
- **双门户/多品牌+共享内核**：满足品牌自治和统一治理。

## 后果与约束
子域、Cookies、CSP、Cors、证书、私有内容缓存、授权都必须被真实验证；文档可见权不等于 API 执行权。

## 关闭条件与证据
跨产品账号越权、外部访问内部操作、移动端与键盘关键任务；NOT_RUN。

> 本 ADR 是架构决策提案。若 PoC、F03–F08 设计或安全审查发现不可满足的约束，必须重新评审；不得将“Proposed”描述为“Approved”。
